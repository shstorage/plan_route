# ADR 0020 — 프로젝트 이름·저장과 막힌 연결점 안내

날짜: 2026-10-12. 범위: 사용자 요청 P07e 하나.

## 확인한 문제

최근 서버 결과에 `port PORT-002 snaps to a physical blocked cell`과 동일한 PORT-003 입력 거부가 기록되어 있었다.
프로젝트는 이미 JSON으로 요청되고 있었다. 저장되지 않아서 생긴 오류가 아니라 연결점의 격자가 물리 장애물·건물 경계로 막힌 경우다.
종전 도면은 INVALID_INPUT 코드만 안내하고 상세 내용을 다른 탭에 숨겼다. 이름 지정과 도면 위 저장도 없었다.

## 구현

- 새 프로젝트는 이름 입력 모달로 생성하고, 도면 위 이름 입력/프로젝트 저장을 제공한다.
  편집 시 JSON을 자동 갱신하며 계산 전에 서버 저장을 요구하지 않는다.
- `EngineeringProject.project_name`은 1~100자의 선택 문자열이며 앞뒤 공백을 제거한다. 한글을 허용한다.
  `project_id`는 저장용 안정 ID로 유지하며 이름을 바꿔도 같은 프로젝트의 개정을 증가시킨다.
- 이름이 없거나 null이면 직렬화에서 이 새 필드를 제외한다. 이름 없는 기존 정규 JSON·문서 해시를 바꾸지 않는다.
  Pydantic 모형과 내보낸 JSON 스키마도 함께 갱신했다. 이름이 존재하는 문서의 해시는 이름도 포함한다.
- 컴파일러가 명시한 실패 Port ID를 정본 JSON에서 찾아 한국어 이름·세계좌표·격자 원인·수정 안내를 제공한다.
  2D/3D에 막힌 연결점 선택 버튼을 제공하고 2D에는 빨간 테두리를 표시한다. 알 수 없는 ID를 추측해 선택하지 않는다.
- NO_PATH와 검색 한도 등 실패 상태를 구분하고 기존 원문은 계산 결과 탭에 유지한다.
  UI 안내는 독립 기하 검증기를 대체하지 않는다. 탐색 마스크·승인 정책·물리 검사를 변경하지 않는다.

## 재현과 검수

새 프로젝트에 펌프 두 개를 (5, 6), (8, 6) m로 배치한다. 첫 펌프 오른쪽 연결점과 두 번째 왼쪽 연결점을 연결한다.
기본 0.5 m 격자·외경 100 mm·보온재 25 mm에서 접속 격자가 주변 기기 팽창 형상과 겹쳐 INVALID_INPUT을 반환한다.
두 번째 기기를 선택해 몸체 왼쪽 X 위치를 14 m로 옮기면 Port도 동반 이동하고 저장 없이 SUCCESS/독립 검증 VALID가 된다.
막힌 연결점을 통과하게 만들거나 기기를 자동 이동해 성공으로 바꾸지 않는다.

직접 실행 결과:

| 명령 | 결과 |

| `uv run python scripts/export_schema.py` | 선택 이름 필드를 포함한 스키마 갱신 |
| `uv run pytest -q` | 216 passed; 기존 의존성 deprecation warning 1건 |
| `uv run ruff check .` | 통과 |
| `cd frontend; npm run test:editor` | 36 passed |
| `cd frontend; npm run test:viewer` | 11 passed |
| `cd frontend; npm run lint` | 통과 |

이름 없는 모형에는 새 필드가 직렬화되지 않는지, 한글 이름의 저장/로드·잘못된 이름 거부,
실제 프런트 작성 함수에서 만들어진 막힌 배치와 수리 배치의 API 계산을 테스트했다.
Windows에서 Node가 출력한 한글 JSON은 UTF-8로 읽는다.
브라우저에서 한글 이름 생성·변경·저장 키 유지·빈 프로젝트 저장/로드와 실패 Port 선택·위치 수정 후 미저장 계산을 직접 확인했다.
검수 산출물은 `data/ui_checks/p07e-1791800792964/`에 보존한다(Git 제외).

## 한계

기본 연결점이 몸체 밖이라도 가까운 다른 기기·벽·경계 또는 큰 배관 외곽 때문에 격자는 막힐 수 있다.
보수적인 격자 판정은 연속공간의 경로 불가능을 증명하지 않는다. 배치와 접속점 위치는 사용자가 수정해야 한다.
표시 이름은 도면의 의미 정본에 저장되지만 파일 이름은 안정 ID를 사용한다. 저장하지 않은 도면의 브라우저 새로고침 복원은 제공하지 않는다.
탐색·기하·승인 알고리즘을 바꾸지 않아 P10 전체 벤치마크는 재실행하지 않았다.
