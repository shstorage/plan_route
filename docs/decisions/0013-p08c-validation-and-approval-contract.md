# 0013 — P08c: 검증 정책, 탐색 보장 범위와 승인 내용 연결

상태: 적용 / 2026-10-11. 대상은 합성 AABB 건물과 단일 배관이다.
기존 검토는 [검토 보고서](../reviews/2026-10-11-implementation-and-thesis-review.md)에 보존한다.

## 독립 검증과 방향

검증기는 원본 세계좌표 선분과 AABB를 사용한다. 탐색 마스크나 탐색 상태로 유효성을 판단하지 않는다.
결과 계약은 `orthogonal_core_canonical_connectors_v2`다.

- 경로 본체는 x/y/z 축에 평행하다. 대각선은 `NON_ORTHOGONAL`이다.
- 첫 본체 구간은 출발 포트의 바깥 방향, 마지막은 도착 포트의 바깥 방향의 반대다.
  불일치는 `PORT_DIRECTION`이다.
- 정확한 출발 포트→포함 셀 중심, 포함 셀 중심→도착 포트 연결선만 방향·직교 검사의 예외다.
  셀 중심은 건물 경계와 해상도로 별도 계산한다. 충돌·경계·자기 간섭 검사에는 예외가 없다.
- 같은 셀의 포트 연결에 본체 구간이 없으면 방향을 검사할 본체가 없다. 이 경우 방향 보장을 주장하지 않는다.
- 탐색 그래프에서 즉시 180도 역행을 제외한다. 격자 본체의 방향 변화마다 bend 비용을 한 번 계산한다.
  연결선 길이는 길이 비용에 포함하지만 포트 연결선의 굽힘은 bend 비용에 포함하지 않는다.

## 경유점 의미

경유점은 물리적 개구부 모델이 아니다. 탐색은 지정 좌표를 셀 중심으로 스냅한다.
독립 검증은 최대 직선 구간으로 경로를 정규화하고 경유점을 순서대로 투영한다.
각 구간에서 이전 경유점 위치 이후의 최근접 투영을 평가하며, 거리·축 조건을 만족하는 최초 후보를 채택한다.
처음 가까운 모서리가 방향 조건을 어겨도 이후 구간을 계속 확인한다.

허용오차는 `sqrt(3)/2 * grid_resolution_m`이며 결과의 `waypoint_tolerance_m`에 기록한다.
`pass_axis`가 있으면 투영 지점에서 접하는 모든 구간은 해당 축의 같은 부호 방향이어야 한다.
따라서 꺾이는 모서리와 180도 역행은 통과로 인정하지 않는다. 경로 시작/끝에서는 한쪽 방향만 평가한다.
방향이 같은 공선점 삽입·삭제는 판정을 바꾸지 않는다. 반복/중첩 경유점은 같은 투영 위치를 공유할 수 있다.
이는 구간별 투영 계약이며, 허용오차 구 안의 임의의 점을 찾아 전역 순서를 최적화하는 별도 문제는 풀지 않는다.
실제 슬리브 지름, 곡률, 허용공차, 승인된 관통부 적용은 P09B 범위다.

## 자기 간섭: 명시적인 꺾은선 정책

외곽 반경 `r`은 배관 반경 + 보온재 + envelope margin이다.
정책 식별자는 `straight_runs_arc_2sqrt3_radius_v2`다.

1. 같은 방향의 공선 구간을 합친다. 원본 세그먼트 번호는 위반 위치 보고에 유지한다.
2. 인접한 두 최대 직선 구간이 역행하면 길이에 관계없이 `SELF_CLEARANCE`다.
3. 비역행 인접 구간은 접합부로 면제한다.
4. 비인접 구간에서는 경로상 거리 `> 2*sqrt(3)*r`인 점 쌍의 유클리드 거리가 `<= 2*r`이면 위반이다.
   부동소수점 판정에는 미터 단위 `1e-9` 허용오차를 사용한다.

기존 `pi*r`은 3축의 짧은 단조 오프셋도 간섭으로 분류할 수 있었다.
축에 평행한 단조 경로는 `arc_length = L1 <= sqrt(3)*L2`이므로 새 임계값은
지름보다 먼 단조 오프셋을 이 정책에서 면제한다. 실제 엘보 곡률·제작 가능성을 증명하는 값이 아니다.
인접 접합부 면제 역시 실제 관 형상을 대신하지 않는다.

비인접 선분의 단일 최근접점만 검사하지 않는다. 선분 매개변수 `(s,t)`의 단위 정사각형을
`offset + t*length2 - s*length1 >= separation` 반평면으로 자르고 그 다각형에서 거리를 최소화한다.
제약 없는 최소점이 가능하면 후보에 넣고, 모든 경계 변의 최소점도 검사한다.
목적함수가 볼록 이차식이므로 내부 최소점 또는 경계 최소점으로 최소 거리를 얻는다.
탐색기의 이산 자기 간섭 검사는 재탐색 유발용 근사이며, 최종 통과는 독립 연속 검증기가 결정한다.

## 결과와 최적성

| 필드/값 | 의미 |
|---|---|
| `NOT_RUN` | 탐색 전 입력/컴파일 실패 |
| `EXACT_GRID` | 순서·진입방향 상태를 포함한 최초 격자 탐색 |
| `HEURISTIC_LEGS` | 앞 구간을 피하는 구간별 재탐색 결과; 최적성 보장 없음 |
| `EXACT_GRID_RETURNED` | 재탐색 실패 후 최초 경로 반환; 최종 검증이 실패할 수 있음 |
| `GRID_OBJECTIVE_EXCLUDING_SELF_CLEARANCE` | 자기 간섭을 제외한 정의된 격자 목적함수에서 최적 |
| `NONE` | 입력 실패, 미발견, 예산 초과, 휴리스틱 결과 또는 최종 검증 실패 |

`initial_search_status`, `fallback_reason`, `fallback_status`와 각 확장 상태 수를 함께 기록한다.
총 확장 상태 수는 최초·재탐색 수의 합이다. 재탐색 예산 초과를 최초 탐색의 불능으로 바꾸지 않는다.
`feasibility_domain=COMPILED_GRID_6_NEIGHBOUR`이며 `NO_PATH`는 이 그래프에 한정된다.
연속공간 경로 존재나 자기 간섭 없는 전체 문제의 불가능을 증명하지 않는다.

## 승인과 기존 JSON

규칙 해시는 ID·종류·severity·scope·parameters·source·definition_revision의 정렬된 JSON에 SHA-256을 적용한다.
UI에서 실행 내용을 수정하면 개정을 올리고 `needs_review`로 바꾸며 이전 승인자·시각·내용 해시를 해제한다.
이전 승인 이력은 보존한다. 명시적인 `POST /api/constraints/approve`가 검토자 이름과 서버 UTC 시각을
현재 개정/해시에 연결하고 상태를 `approved`로 바꾼다. 오래된 내용의 승인은 컴파일·검증에서 차단한다.

이력이 없는 기존 `approved` 규칙은 호환 입력으로 허용하되 `legacy_approval_rule_ids`로 식별한다.
그 입력에는 내용 변경을 판별할 과거 해시가 없다. 현재 내용을 검토해 재승인해야 새 보장을 얻는다.
승인 해시만 지우고 기존 이력을 남긴 입력은 실행되지 않는다.
전체 이력까지 삭제한 JSON을 구형 입력과 구별하거나 검토자 신원을 인증하는 기능은 없다.
이는 로컬 연구자의 승인 선언 기록이며 변조 방지 감사 저장소나 인증 시스템은 아니다.

새 기본 필드 때문에 저장된 구형 프로젝트의 정규화 해시가 바뀐다. 로더는 먼저 저장 원문 해시를 검증하고
유효한 원문에만 기본값을 채워 정규화 해시를 반환한다. 원본 파일과 개정 번호는 유지한다.
원문 변조를 기본값 마이그레이션으로 허용하지 않는다.

## 검수와 후속 범위

Python 148, editor 20, viewer 10 테스트 통과. Ruff, frontend lint/build 통과.
R1 역행(분할 전후), R2 이후의 유효 경유점, R3 포트 방향·대각선 반례를 재실행했다.
별도 9칸 그래프의 Bellman–Ford 기준 계산으로 네 경유점 시나리오의 A*/Dijkstra 비용을 대조했다.
이는 분석적 회귀 사례이며 모든 장면의 완전성 증명이나 성능 우월성 실험이 아니다.
브라우저 조작/WebGL 시연은 미실시다. 반복 run 보존, 입력 snapshot, compile/search/validate/total 계측,
시드 장면과 비교 통계는 P10A 이후에 수행한다.
