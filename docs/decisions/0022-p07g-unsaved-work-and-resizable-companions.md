# ADR 0022 — P07g 저장 안내·미저장 보호·보조 창 크기 조절

날짜: 2026-10-13. 범위: 사용자 요청의 프로젝트 관리·2D/3D 보조 창 개선 하나.
기존 P10 문서 작업은 유지하며 탐색·검증·백엔드 저장 계약은 변경하지 않는다.

후속 P07h는 [ADR 0023](0023-p07h-window-edges-and-detached-views.md)에서 내부 창의 여백 없는 최대화,
8방향 테두리 조절과 별도 브라우저 창을 추가했다. 아래 별도 OS 창 미지원은 P07g 당시의 한계다.

## 저장 동작 검토

- `fixtures/`는 패키지에 포함된 합성 예제 정본이다. 예제 불러오기는 새 `SYNTH-COPY-*` ID의 작업 복사본을 연다.
- 처음 화면과 새 프로젝트는 `SYNTH-NEW-<밀리초 시각>` ID로 브라우저 메모리에만 준비한다.
  생성·편집·계산은 프로젝트 저장과 별개다. 서버 저장 요청을 완료해야 `data/projects/{project_id}.json`이 생긴다.
- 한글 `project_name`은 표시 이름이다. 저장 파일명은 영문/숫자 ID를 쓴다. 이름 변경도 같은 파일의 개정을 올린다.
  저장본은 `project`, `revision`, `updated_at`, `document_hash`를 담은 wrapper다.
- 저장은 임시 파일을 쓰고 flush/fsync한 뒤 원자적으로 교체한다. 같은 ID의 최신 파일 하나를 보존하며
  개정 번호는 과거 문서의 복원 기능이 아니다. 프로젝트 백업 대상은 `data/projects/`다.
- `data/results/`는 요청 내용 hash 기반 계산/검증 결과다. 동일 요청은 교체된다.
  프로젝트 재로드는 도면을 열고 결과 화면은 초기화한다. 연구 반복 기록은 별도 `data/benchmarks/`에 보존한다.
- `data/benchmarks/`와 `data/ui_checks/`는 일반 편집기 사용에 필수인 데이터가 아니다.
  전자는 연구 실행/원본/그림, 후자는 브라우저 검수 결과·스크린샷·임시 프로필이다. 이번에 삭제하지 않았다.

## 화면 개선

프로젝트 탭에 현재 ID와 `data/projects/{id}.json`을 보여 준다. 저장 완료/로드 여부에 따라
“저장 파일” 또는 “저장 시 사용할 파일”로 표시하며 API 서버의 프로젝트 폴더 기준임을 알린다.
목록에도 파일명을 표시한다. 저장 성공 안내에는 파일명·개정·시각을 포함한다.
새 프로젝트 안내에는 생성 버튼만으로 파일이 생기지 않음을 명시한다.

새 프로젝트 만들기·예제 불러오기·저장 목록/ID 불러오기를 공통 미저장 보호로 연결한다.
선택지는 “저장하고 계속 / 저장하지 않고 계속 / 취소”다.
저장 실패와 잘못된 JSON은 전환을 중단하고 현재 문서·확인창을 유지한다.
저장 중에는 확인창을 닫거나 중복 선택하지 못한다. 서버 저장본은 전송한 snapshot으로 기록한다.
이름 입력 draft를 부모 상태에 두어 blur 전에 떠나는 경우에도 미저장으로 판정한다.

새로고침·다른 페이지 이동·브라우저 탭 닫기에는 미저장 상태일 때만 `beforeunload`를 등록한다.
저장/Undo로 마지막 저장본과 같아지면 경고를 해제한다. 처음 열린 그대로의 빈 시작 화면은 이탈을 경고하지 않는다.
사용자가 만든 새 프로젝트·예제 복사본은 의도한 작업이므로 저장 전 이탈을 경고한다.
2D/3D/프로젝트/결과 탭 전환과 보조 창 닫기는 문서를 유지하므로 이탈 확인을 하지 않는다.

브라우저 이탈 확인 문구는 브라우저가 정하며, 실제 사용자 조작이 있어야 나타난다.
모바일 강제 종료 등에서 항상 발생하는 이벤트가 아니므로 자동복구 보장은 아니다.
근거: [MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event).

## 보조 창

기존 CSS `resize: both`만으로는 조절부가 눈에 띄지 않았고 3D 높이는 360 px로 고정되어 있었다.
명시적인 오른쪽 아래 손잡이, 제목줄 최대화/원래 크기, 드래그 이동 안내를 추가했다.
손잡이는 마우스/포인터 드래그와 방향키(20 px, Shift 80 px)를 지원한다.
창 크기·위치는 화면 안으로 제한하고 화면 축소 시 재보정한다. 최소 크기도 작은 화면을 넘지 않는다.
이동은 최대화 상태에서 비활성화하고 최대화 전 크기/위치를 복원한다.

3D canvas는 남은 창 높이를 사용한다. 2D 보조 창은 별도 `companion` 표시 속성을 받아
`ResizeObserver`의 실제 영역 폭/높이를 Stage에 반영한다. 일반 2D 배치 화면의 높이 정책은 유지한다.
창을 작게 만들면 본문은 스크롤하고 제목·손잡이는 계속 보인다.
이 크기 조절은 UI 상태이며 EngineeringProject의 세계좌표·JSON에는 저장하지 않는다.
설정 모달이 열린 동안 Escape로 뒤의 보조 창이 함께 닫히지 않도록 했다.

첫 브라우저 실행에서 2D 최대화가 canvas 높이를 늘리지 못하는 것을 검출했다.
flex 영역의 고정 높이와 최소 크기를 수정한 뒤 전체 브라우저 검수를 재실행해 통과했다.
검수는 파일 위치/이름, 저장 전 서버 404, 미저장 이름 draft, 취소, 네트워크 차단 저장 실패,
저장 후 새 프로젝트, 잘못된 JSON, 저장 없이 전환, 실제 native refresh 확인/취소,
저장 후 경고 해제, 3D 드래그 크기/최대화 복원, 2D 실제 높이 증가, 작은 화면 내 창 배치를 포함한다.
기존 API 저장/로드·경로 계산·연결·Undo·모바일 흐름도 유지했다.
스크린샷을 직접 확인해 제목줄·창 내부 화면·조절 손잡이가 보이는지 확인했다.

결과/스크린샷: `data/ui_checks/p07g-1791856720630/` (Git 제외).
실행은 API :8000과 Vite :5173을 먼저 켜고 프로젝트 루트에서 위 Node 명령을 사용한다.
검수 스크립트는 새 테스트 프로젝트 파일을 만들며 기존 사용자 저장 파일은 수정하지 않는다.

## 남은 한계

파일 저장은 로컬 단일 프로세스이며 다중 사용자/브라우저 간 덮어쓰기 충돌 검출은 없다.
이 단계는 자동저장·비정상 종료 복구·개정별 문서 보존·다른 이름으로 저장을 추가하지 않는다.
표시 이름은 중복 가능하다. 브라우저 새로고침 후 저장 목록에서 직접 다시 불러온다.
보조 창 크기는 열린 동안만 유지되며 닫았다 다시 열면 기본 크기로 돌아간다.
실제 별도 OS 창/모니터 이동 기능이 아닌 웹 페이지 내부 보조 창이다.
플랜트 전체 층·규칙·드래그의 모든 회귀 및 P09 확장은 다음 요청의 별도 작업이다.
