# ADR 0021 — 저장 목록과 예제 작업 복사본

날짜: 2026-10-12. 범위: 사용자 요청 P07f 프로젝트 관리 검수 하나.

## 발견

서버 파일에는 사용자가 이름을 바꾸어 저장한 `test-11` 항목과 수정한 플랜트 저장본이 있었다.
종전 UI/API에는 저장 목록이 없었고 ID 직접 입력으로만 불러올 수 있었다.
저장 이후에도 프로젝트 탭의 오래된 작업 라벨이 ‘도면 편집 중’으로 남아 저장 상태와 모순됐다.
예제 버튼은 원본 fixture를 다시 열며 저장한 수정본을 여는 기능과 구분되지 않았다.

## 구현

- `GET /api/projects`는 `{projects, issues}`를 반환한다. 모든 문서를 기존 로더로 검증하고 최신 수정 시각/ID 순으로 정렬한다.
  이름·ID·개정·수정 시각·기기/배관 수를 요약한다. 손상/해시 오류 파일은 제외하며 경고로 알리고 삭제하지 않는다.
- 프로젝트 탭에 저장 목록·이름/ID 검색·새로고침·선택 불러오기를 추가한다. ID 직접 입력은 보조 항목으로 유지한다.
  저장 후 목록을 갱신하고, 목록 로딩/실패/비어 있음/검색 결과 없음/손상 파일을 구분한다.
- 이름 변경 저장은 같은 ID의 개정을 올리고 같은 목록 항목의 이름을 갱신한다. 조회는 이름이 아닌 안정 ID를 사용한다.
- 저장/로드 시 실제 JSON의 서명을 기록하고 편집/Undo 이후 현재 문서와 비교해 저장 상태를 표시한다.
  세션 안에서 새 프로젝트를 만든 뒤 Undo로 돌아갈 때도 마지막 저장 기준을 프로젝트 ID별로 기억한다.
  상단·프로젝트 탭의 상태는 이 같은 기준을 사용한다. 목록 객체 수는 마지막 서버 저장본의 수다.
- 예제 버튼은 새로운 `SYNTH-COPY-*` ID와 이름의 작업 복사본을 만든다. 객체 ID·배관/규칙 참조는 유지한다.
  기기 추가 등 수정은 복사본 저장에 반영되고, 목록에서 다시 열면 보존된다. 원본 fixture와 기존 저장본은 유지한다.
  예전 고정 예제 ID로 저장한 문서도 목록에서 불러올 수 있다.

API에서는 빈 목록, 이름 없는 과거 JSON, 이름 변경과 개정/객체 수, 잘못된 JSON·해시 오류의 격리,
결정론적 최신순과 예제 API 호환을 확인했다. 정렬 테스트는 제어된 UTC 시각을 사용한다.
브라우저에서는 test1 생성 → test11 저장 → 목록 반영 → 페이지 새로고침 → 목록 선택 재로드를 직접 확인했다.
작성한 기기·Port·배관 JSON이 서버 정규 JSON과 같은지 대조했다.
소형 예제를 복사하고 펌프를 추가한 후 저장 → 다른 프로젝트 → 목록 불러오기에서 추가한 기기가 유지되고 원본 API JSON은 그대로임을 확인했다.
기존 UI/3D/연결·오류 복구 흐름과 모바일 가로 넘침도 검수했다.

결과·스크린샷: `data/ui_checks/p07f-1791801967301/` (Git 제외).
재현은 개발 서버 두 개 실행 후 프로젝트 루트에서 `node scripts/check_editor_ui.mjs`를 실행한다.

## 남은 한계

로컬 단일 프로세스 파일 저장이다. 다중 사용자 편집 충돌·서버 페이지 나누기·개정별 과거 문서 복원은 제공하지 않는다.
새로고침 후 자동으로 이전 도면을 여는 기능은 없고 저장 목록에서 불러온다. 이름은 중복 가능하며 ID로 구분한다.
저장하지 않은 변경은 서버 목록에 반영되지 않는다. 계산 결과는 기존 `data/results/` 저장 정책을 사용하며 프로젝트 재로드 시 계산 화면을 초기화한다.
