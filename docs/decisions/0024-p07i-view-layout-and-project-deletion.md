# ADR 0024 — P07i 보기 창 사용성·화면 비율·저장 프로젝트 삭제

날짜: 2026-10-13. 사용자 요청의 보기 창 및 저장 목록 사용성 개선을 P07i 하나로 수행한다.
EngineeringProject JSON·solver·Validator·규칙 승인 계약은 유지한다.

## 창 동작과 배치

기존 ‘메인 창 보기’는 부모의 `window.focus()`만 호출했다.
[MDN Window.focus](https://developer.mozilla.org/en-US/docs/Web/API/Window/focus)는 브라우저 설정에 따라
요청이 실패하거나 창이 앞으로 오지 않을 수 있다고 명시한다.
버튼을 **메인에서 계속**으로 바꿔 메인의 같은 2D/3D 탭을 선택하고 보조 창을 닫는다.
메인 탭으로 키보드 포커스와 스크롤을 이동하며 OS 창 포커스도 요청한다.
기하·선택·계산 결과를 다시 로드하지 않으며 다른 보조 창은 유지한다.
OS의 전면 창 결정은 브라우저/운영체제에 달려 있다.

화면 내 **함께 보기**는 한 화면에서 2D/3D를 비교할 때,
**새 창**은 다른 모니터에 별도로 둘 때 유용하므로 둘 다 유지한다.
두 버튼을 탭 옆 한 그룹에 모으고 각 기능에 붙는 SVG 아이콘과 설명을 제공한다.

- 별도 창은 기본 960×900 px, 화면 내 창은 최대 960×860 px로 시작하며 화면 경계를 지킨다.
- 보조 창의 콘텐츠 폭은 1120 px 이내로 제한하고 중앙에 놓는다. 최대화·8방향 resize는 유지한다.
- 2D 속성 패널은 브라우저 전체 폭 대신 실제 편집기의 폭으로 배치한다.
  콘텐츠가 760 px 이하이면 도면 아래로 내리고 도면 높이를 확보해 두 영역이 겹치지 않게 한다.
  근거: [MDN container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries).
- 3D 카메라는 건물 중심을 보고 실제 canvas의 가로/세로 비율과 건물의 8개 모서리로 거리를 계산한다.
  canvas 비율 변경·preset·카메라 리셋 때 전체 건물을 다시 맞춘다. 일반 객체 편집으로 카메라를 초기화하지 않는다.
- 2D와 3D의 ResizeObserver는 소속 창에서 생성한다. Canvas의 크기 측정도 새 창의 observer를 사용한다.
  부모 JS realm의 observer/RAF에만 의존하면 부모가 배경일 때 새 창의 측정·그리기가 지연되는 것을 확인했다.
  별도 3D는 소속 창의 RAF에서도 pending 프레임을 진행하고, 2D는 소속 창에서 변경 후/드래그 중에 그린다.
  메인 창 RAF를 멈춘 검수에서도 새 창 크기 측정과 실제 렌더·카메라 투영이 갱신됐다.
- 삭제·미저장 확인의 초기 포커스는 dialog가 열린 뒤 취소 버튼에 명시적으로 놓는다.

## 삭제 계약

저장 목록의 **삭제**는 즉시 실행하지 않는다. 확인창에 이름·파일명·저장 개정·복구 불가를 표시하고
취소를 기본으로 둔다. 실행 중 버튼을 잠그고 오류는 확인창 안에 표시하며 작업 내용을 유지한다.
메인에서 확인하는 동안 별도 창의 편집 본문도 inert로 둔다.

`DELETE /api/projects/{project_id}?expected_revision=<목록의 개정>`은 저장 파일 하나만 삭제한다.
ID/경로 검사와 무결성 재검증 후 기존 저장 lock 안에서 개정을 비교하고 `unlink`한다.
목록 확인 뒤 다시 저장되어 개정이 달라지면 HTTP 409·REVISION_CONFLICT로 중단한다.
성공은 HTTP 200·`{project_id, deleted: true}`, 없는 파일은 404·NOT_FOUND,
검증 실패는 422·INVALID_INPUT, 파일 I/O 실패는 503·STORAGE_ERROR다.
`demo`/`starter` 원본 endpoint는 409·PROTECTED_PROJECT로 보호하고 CORS에 DELETE를 추가한다.
계산 결과 파일은 연구 기록으로 유지한다.

현재 작업의 저장 파일을 삭제해도 화면 JSON·Undo/Redo·선택·결과는 유지한다.
저장 signature·개정 정보·저장 캐시를 해제하고 미저장 상태와 이탈 확인을 적용한다.
최초 빈 화면과 내용이 같은 저장본을 삭제한 경우도 이탈 보호 대상이다.
다시 저장하면 같은 ID의 파일을 개정 1로 생성하고 미저장 표시를 해제한다.
다른 저장 프로젝트를 삭제하면 현재 작업의 저장 상태는 바뀌지 않는다.

Node 테스트·브라우저와 최종 build는 승인된 명령으로 샌드박스 밖에서 실행했다.
build의 샌드박스 실행은 Windows 프로세스 생성 EPERM으로 실패하여 밖에서 재실행했다.
API 삭제 테스트는 임시 저장소를 사용하며 선택 파일·개정 충돌·원본 보호·경로·I/O 실패·손상 파일 보존을 검사한다.
카메라 단위 테스트는 원점이 다른 건물과 portrait/정사각/wide 화면에서 모서리의 투영 경계를 검사한다.

브라우저에서는 기존 90개와 버튼 그룹·기본 비율·1920 px 창 중앙 배치,
부모 focus를 무효화해도 두 방향으로 메인 탭 전환/창 닫기/JSON 보존,
960 px 2D의 옆 속성 패널·640 px 창의 하단 속성 패널,
삭제 취소·취소 초기 포커스·별도 창 잠금·개정 충돌·통신 실패·목록 갱신·현재 문서 보존·재저장을 확인했다.
실제 열린 3D 창의 렌더 frame과 건물 중심/8개 모서리 투영도 검사한다.
2D의 실제 Konva Stage 크기와 건물 전체가 canvas 내부에 들어가는지도 검사한다.
메인 RAF를 차단한 상태의 별도 2D/3D 측정·그리기를 별도로 확인한다.

검수 스크립트는 Vite 개발 서버의 렌더 모듈을 검사에만 사용한다. 앱 코드가 이 검사 코드에 의존하지 않는다.
초기 검수에서 scrollbar를 포함한 전체 폭과 콘텐츠 폭의 차이, 좁은 창의 flex/grid 겹침,
native dialog showModal 이후 취소 포커스, 캡처 전 렌더 대기 문제를 확인해 보완했다.
닫힌 창의 렌더 root가 정리되기 전 측정되는 것을 피하도록 실제 열린 창만 검사한다.
`--views-only`는 이번 보기/삭제 23개 흐름만 빠르게 재현하는 옵션이다. 전체 90개 회귀를 수행한 것으로 보고하지 않는다.

최종 전체 기록: `data/ui_checks/p07i-1791870334370/` (Git 제외).
집중 기록: `data/ui_checks/p07i-1791870302364/` (Git 제외).
`result.json`, `plant-reports.json`, `viewer-frame.json`, `plan-frame.json` 및 2D/3D·삭제 확인 캡처를 보존했다.
최종 캡처에서 별도 창의 기하·중앙 배치·좁은 2D의 전체 건물 표시를 직접 확인했다.

## 수동 재현과 한계

1. API :8000과 Vite :5173 실행 후 페이지를 열고 같은 그룹의 ‘함께 보기’와 ‘새 창’을 비교한다.
2. 별도 창을 960 px와 넓은 화면에서 확인하고, 2D 창을 좁혀 도면 아래로 속성이 이동하는지 본다.
3. 별도 창의 ‘메인에서 계속’을 누르면 창이 닫히고 메인의 해당 탭에서 작업 내용이 이어진다.
4. 프로젝트 목록의 삭제를 누른 뒤 취소를 확인하고, 다시 삭제해 목록과 저장 상태가 갱신되는지 본다.
5. 현재 작업의 저장 파일을 지워도 편집 JSON이 유지되며 다시 저장할 수 있는지 확인한다.

브라우저 재현은 두 서버 실행 후 `node scripts/check_editor_ui.mjs`다.
물리 듀얼 모니터 이동·OS 창 전면 전환·Chrome GUI는 자동 검수하지 않았다.
파일 삭제의 휴지통/복원, 저장소의 다중 프로세스 충돌 조정은 제공하지 않는다.
새 의존성·LLM·다배관·CAD export·P10 재실행은 포함하지 않는다.
