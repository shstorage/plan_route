# 2026-10-13 P10 논문 주장 범위와 선행연구 비교표

검토 기준: 현재 코드 `2e4f51b`, 보존 P10B/C 배치, 공개 논문 본문·초록.
작업 범위는 P10 문서 보완 하나다. 이 문서는 논문에 사용할 주장·분모·근거 수준을 정리한 초안이며,
전체 문헌의 체계적 검토나 선행연구 대비 우월성 판정은 아니다.
이전 [구현 검토](2026-10-11-implementation-and-thesis-review.md)는 당시 기록으로 보존한다.

## 1. 연구 범위와 사용할 기여 문장

권장 제목은 **「추적 가능한 설계 제약의 공간 컴파일과 독립 기하 검증을 이용한 3차원 배관 경로 생성 및 변경 영향 분석」**이다.
대상은 합성 AABB 공간의 단일 배관, 승인된 `KEEP_OUT`/`MIN_CLEARANCE`, 방향·순서 상태의 6방향 격자 탐색이다.
길이·bend 목적함수와 포트 연결선 예외, 경유점 허용오차, 자기 간섭 정책은
[ADR 0013](../decisions/0013-p08c-validation-and-approval-contract.md)의 정의를 따른다.

논문 기여 초안:

> 본 연구는 합성 3차원 배관 문제에서 승인 규칙의 내용·출처·대상 객체를 공간 차단과 경로 검증 결과에
> 연결하는 재현 가능한 실험 체계를 구성하였다. 동일한 물리 입력에서 규칙 추가·이격 변경·개별 제거 및
> 중립 대조를 실행하고, 변경 전후 경로를 서로의 규칙으로 다시 검사하여 비용·형상 변화와 위반 근거의
> 연결을 기록하였다. 별도 소형 격자 기준 계산과 해석적 경로를 이용하여 격자 목적함수의 비용 일치,
> 보수적 차단으로 인한 경로 미발견, 제한된 검증 반례를 구분해 평가하였다.

이는 이 연구에서 구성하고 관찰한 방법의 설명이다. “최초”, “실무 적용 입증”, “기존 방법보다 우월”은
사용하지 않는다. 독립 Validator는 생산 solver의 마스크를 재검사하지 않는다는 구조적 의미이며,
구현 오류가 없다는 증명이나 외부 기관의 독립 검증을 뜻하지 않는다.

H2의 “방향 상태가 없는 A*보다 정확하다”는 비교는 본 벤치마크에서 별도 실험군으로 실행하지 않았다.
방향 상태·bend 계약의 구현과 단위 검수만 설명한다. RQ4/H4는 LLM 미구현으로 평가하지 않았다.
P10B는 같은 feasible set과 objective의 알고리즘 대조이고, P10C는 규칙을 바꾼 영향 분석이다.
서로 다른 규칙 집합의 총비용을 알고리즘 우열 지표로 사용하지 않는다.

“기대 계약과 일치”에는 의도한 실패도 포함된다. 이를 경로 성공률 100%로 바꾸지 않는다.
연속 witness 성공률의 분모는 알려진 feasible 고유 장면이고 반복 실행·해상도를 새 표본으로 더하지 않는다.
시드가 같은 family들은 상관될 수 있다. 개발 cluster 5개·평가 cluster 2개의 bootstrap 구간은 기술 통계다.

| split / 격자 | known-feasible 성공 (각 알고리즘) | 성공 exact paired 장면 | 평균 시간 차이 Dijkstra−A* (ms) | 95% seed cluster 구간 (ms) | 최대 비용 차이 |
|---|---:|---:|---:|---|---:|
| 개발 / 1.0 m | 25/30 | 25 | 2.847 | [2.473, 3.376] | 0 |
| 개발 / 0.5 m | 30/30 | 30 | 95.562 | [90.769, 100.355] | 0 |
| 평가 / 1.0 m | 10/12 | 10 | 3.173 | [3.144, 3.202] | 0 |
| 평가 / 0.5 m | 12/12 | 12 | 93.301 | [93.090, 93.511] | 0 |

시간은 장면별 3회 서비스 시간의 중앙값을 먼저 구한 뒤 같은 장면에서 차이를 평균한 것이다.
compile/search/validate를 포함하고 API 파싱·저장·통신·별도 oracle 계산은 제외한다.
coarse/fine에서 성공 장면 집합이 다르므로 이 집계 차이를 해상도의 순수 효과로 해석하지 않는다.
이 측정 환경의 A*–Dijkstra 시간 차이는 선행논문 시스템의 속도 비교가 아니다.

P10C 평가 A*의 성공 exact 대조에서 KEEP_OUT 추가의 평균 목적함수 변화는 1 m에서 +16,
0.5 m에서 +14였다. 이격 0.25→1.25 m 변경은 두 해상도에서 +2였고,
출처 수정·중복 규칙 추가/제거 대조는 0이었다. 각 집계는 **평가 물리 장면 2개**다.
목적함수 변화량을 경로 길이(m)로 표기하지 않는다. 규칙 제거 후 원래 요구를 위반할 수 있으므로
음의 비용 변화도 원래 요구에 대한 개선으로 해석하지 않는다.

## 5. 재현과 자료 공개의 범위

검수한 보존 배치:

- P10B: `data/benchmarks/20261011T135415Z-0ee8d964e0764083be8e249dd079c18a/`
- P10C: `data/benchmarks/20261012T080959Z-d110cef3f05242e7b9a7acc6fdcda1bf/`

두 배치 모두 실행 당시 `git_dirty: true`다. 당시 HEAD는 각각 `392305b`와 `00b6107`이며,
커밋만 checkout해서 정확한 실행 소스가 복원된다고 표현하지 않는다. `environment.json`의 manifest와
`source.zip` 내부 모든 파일을 SHA-256으로 대조했다(P10B 41개, P10C 44개).
현재 astar/compiler/geometry/path_validator/routing 및 uv.lock 6개 파일은 두 archive와 일치했다.
이 비교는 명시한 6개 파일에 한정하며 프런트엔드·전체 패키지 동일성 검사는 아니다.

```powershell
# 프로젝트 루트: 보존 배치의 CSV/summary 합계와 source.zip hash 검사
uv run python docs/reviews/evidence/audit_benchmarks.py

# 새 배치 생성: 기존 배치를 덮어쓰지 않음, 시간 숫자는 달라질 수 있음
uv run python scripts/run_benchmark.py --config benchmarks/comparison.json
uv run python scripts/run_benchmark.py --config benchmarks/changes.json
```

검수 스크립트는 solver를 실행하지 않고 숫자·archive의 일관성을 확인한다.
이번 JSON snapshot에는 표에 필요한 집계와 원본 hash만 담았다. 원본 실행별 경로·입력·그림은
Git 제외된 로컬 배치에 있으므로 새 clone에는 없다. 위 audit은 지정한 보존 배치가 없으면 실패한다.
신규 실행은 다른 batch ID를 만들며, 이 문서의 역사적 배치를 대신 검수한 것으로 간주하지 않는다.
논문 결과를 완전히 공개하려면 해당 배치 전체의 별도 배포가 필요하다. 이번 작업은 배포하지 않았다.
