## 3. 코드 검토 결과 — 중요도 순

### R1. 높음: 자기 간섭 판정이 선분 분할에 따라 달라짐 — 재현됨

위치: `src/plan_route/services/path_validator.py:119`, 특히 138–139행.
바로 인접한 선분 쌍을 모두 제외하므로, 한 선분을 따라 갔다가 그대로 되돌아오는 두 선분을 검사하지 않는다.

장애물 없는 공간, 반경 0.1 m에서 다음 경로를 실행했다.

- `(2,2,2) → (6,2,2) → (3,2,2)` → **VALID**, 위반 없음.
- 동일 경로에 공선상 점만 추가한 `(2,2,2) → (4,2,2) → (6,2,2) → (5,2,2) → (3,2,2)`
  → **INVALID_ROUTE**, `SELF_CLEARANCE`.

형상은 동일한데 판정이 바뀐다. 독립 검증기/API에 임의 polyline을 넣거나 경로 단순화를 추가할 때 문제가 된다.
현재 모든 solver 출력에서 누락된다는 의미는 아니다. 현재 단위 테스트가 이 불변성을 다루지 못한다.

필요 조치: 인접 선분의 180도 역행/겹침을 별도 검사하고, 공선점 삽입·삭제 불변성을 시험한다.
`π × radius` 면제와 선분 쌍의 최근접점 한 쌍만 이용하는 방식도 수학적 적용 범위를 검토한다.
유한 굽힘 반경 엘보를 모델링한 물리 검증으로 표현하지 않는다.

### R2. 높음: 경유점 검증이 최초 근접 구간에 고정되어 통과 축을 오탐 — 재현됨

위치: `src/plan_route/services/path_validator.py:199`.
거리 조건을 처음 만족하는 구간에서 탐색을 멈추고, 그 뒤에서 통과 방향을 검사한다.
그 구간이 방향을 만족하지 않아도 이후의 적합한 통과 구간을 찾지 않는다.

격자 1 m, 경유점 `(4.1,3.9,2.5)`, 통과 축 x에 대해:

`(2.5,4.5,2.5) → (3.5,4.5,2.5) → (3.5,3.5,2.5) → (4.5,3.5,2.5) → (5.5,3.5,2.5) → (6.5,3.5,2.5)`

뒤쪽 x 방향 구간은 허용오차 이내로 곧게 통과하지만 앞쪽 모서리가 먼저 선택되어
`WAYPOINT_DIRECTION`(segment 0)이 발생했다.
필요 조치: 거리·방향·순서를 동시에 만족하는 통과 후보를 탐색한다.
여러 후보/겹치는 허용영역에서 순서 판정도 함께 검증한다.

### R3. 높음: VALID가 보증하는 범위가 포트 방향·직교성과 다름 — 재현됨

위치: `path_validator.py:259` 이후; 비교 대상 `astar.py:449` 이후.
solver는 격자의 첫 이동/마지막 도착 방향을 제한한다. validator는 포트 위치만 검사한다.
포트가 +x/-x여도 y 방향 직선 `(2,2,2) → (2,6,2)`를 **VALID**로 판정했다.
대각선 `(2,2,2) → (6,6,2)`도 **VALID**다.

일반 polyline 충돌 검사라는 한정된 계약이면 대각선 자체는 오류가 아니다.
그러나 UI·논문이 VALID를 "포트 방향과 직교 배치까지 검증됨"으로 해석하면 검증 누락이다.
포트–격자 연결선은 원래 비직교를 허용하며 해당 굽힘을 비용에서 제외하므로,
먼저 연결선 예외와 전체 경로의 방향/굽힘 의미를 정의한 뒤 solver와 validator에 반영해야 한다.

### R4. 높음: 경유점/최적성/불능의 의미를 제한해야 함 — 코드 확인

- `astar.py:570–603`: 자기 간섭 발생 후 구간별 재탐색은 휴리스틱이다.
  이 사실을 message와 UI에 이미 알리는 점은 좋다. 하지만 결과의 `algorithm`은 계속 astar/dijkstra이고
  구조화된 `search_mode`, `optimality_guarantee`, `fallback_reason`이 없다.
  연구 CSV에서 최적해와 휴리스틱 해를 구분하지 않으면 비교가 왜곡된다.
- 방향·방문 순서 상태의 A*는 자기 간섭 이력을 상태에 포함하지 않는다.
  따라서 최초 탐색의 최적성은 **자기 간섭을 제외한 해당 격자 목적함수**에 대한 것이다.
- `waypoint_tolerance_m`: 허용오차는 `√3/2 × grid_resolution_m`이다.
  격자 1 m면 약 0.866 m이므로 물리 슬리브 중심/반경 허용오차로 해석할 수 없다.
  실제 개구부·벽 관계·승인 개구부 전용 통과는 P09B 미구현이다.
- 보수적 whole-cell 차단에서 `NO_PATH`는 그 격자에 경로가 없다는 의미다.
  연속공간에서도 불가능하다는 증명이 아니다. 경유점이 없는 경로의 자기 간섭 재탐색도 현재 없다.
- h=0 비교는 휴리스틱 검증에 유용하지만 A*와 상태전이/비용 코드를 공유한다.
  공통 버그까지 독립적으로 검출한 최적성 증명으로 쓰지 않는다.

필요 조치: 결과 계약에 탐색 방식/보장 범위를 추가하고 작은 별도 기준 계산과 해상도 민감도 실험을 수행한다.

### R6. 중간: 출처 필드가 승인 이력·변경 원인 증명까지 제공하지 않음 — 코드 확인

## 4. 현재 구현의 장점

1. **UI와 계산을 분리한 단일 EngineeringProject**: 2D/3D의 같은 장면으로 실험 입력을 점검하고 재사용 가능하다.
2. **벌점이 아닌 Hard Rule 배제**: 금지구역 침범을 짧은 경로로 상쇄하지 않으며, 미승인 입력도 실행을 막는다.
3. **격자와 연속 기하의 다른 판정 방식**: mask 재확인보다 강한 검증 구조다. R1–R3을 고치면 연구의 핵심 근거가 된다.
4. **방향·순서 상태와 비용 분해**: 단순한 구간별 연결보다 분석하기 좋은 모델이며, exact/heuristic 구분의 기반이 있다.
5. **경유점·마진·합성 플랜트 예제**: 재설계/순서 변경/좁은 통로 등 유의미한 실험군을 만들기 쉬워졌다.
6. **실패 결과를 시각적으로 확인**: INVALID_ROUTE 경로와 위반 구간을 반환하므로 실패를 숨기지 않고 분석 가능하다.

이들은 좋은 구현/실험 설계상의 장점이다. 각 요소 자체의 최초 발명이나 선행연구 대비 우월성은 아직 입증하지 않았다.

| [Kong et al., 2026](https://www.sciencedirect.com/science/article/pii/S2092678226000609) | A* 비용 가중치 문제에 다중 LLM 전문가 체계 적용 | 가중치 조정과 다른 연구 질문: 규칙 변경의 추적·검증을 평가 |
| [Eastman et al., 2009](https://doi.org/10.1016/j.autcon.2009.07.002) | 규칙 해석, 모델 준비, 규칙 실행, 보고의 단계적 체계 | compiler/validator 분리라는 일반 구조만으로 신규성 주장 금지 |
| [Xie et al., 2022](https://doi.org/10.3390/buildings12070934) | MEP 규칙 지식관리, 규칙 편집과 BIM 속성·간격 검사 | 규칙 JSON·관리 UI·간격 검사만으로도 차별화 부족 |
| [Anand et al., ARCHER, 2026 v2](https://arxiv.org/abs/2607.25566v2) | 실행 가능한 규정 검증 코드와 감사 가능한 결정론적 실행 체계; 프리프린트 | 결정론·검증 가능성도 인접 분야에 이미 존재. 배관 특화 실험으로 범위를 좁힘 |

권장 기여는 다음 두 가지를 **실험으로 입증하는 것**이다.

- **C1: 규칙 변경의 재현 가능한 영향 분석** — 규칙 출처/개정 → 공간 차단 → 생성 경로 → 연속 검증을
  동일 입력 snapshot으로 연결한다. 규칙별 변경 전후 길이·굽힘·형상 차이와 근거 연결의 완전성을 측정한다.
- **C2: 격자 근사와 독립 검증 사이의 불일치 정량화** — 해상도, 반경, 마진, 경유점 위치를 바꾸어
  오검출·누락·보수적 차단·재탐색의 품질/시간 비용을 분리한다. 명확히 설계한 반례와 공개 실행 입력을 제공한다.

후보 기여의 적합성은 검토자의 판단이며 성능 우위가 확인된 결과가 아니다.
새 A* 알고리즘 발명보다는, **기하 제약의 의미와 변경 영향을 검증 가능한 실험 체계로 만드는 공학적 연구**가 현재 코드에 맞다.

## 6. 남은 작업과 실험 설계

우선순위는 **P08c 정확성/계약 보완 → P10A 예비 실험 → 필요한 P09 선택 → P10B/C 본 실험·변경 분석**이다.
다배관·LLM·온톨로지·DXF를 전부 만들어야 학위 연구가 되는 것은 아니다.

| 실험 | 비교/정답 | 지표 |
|---|---|---|
| E1 격자 최적성 | 같은 상태/규칙/목적함수의 A* vs Dijkstra; 별도 소형 완전탐색/명시적 그래프 기준 계산 | 비용 차이, 확장 상태 수; fallback 분리 |
| E2 검증 신뢰도 | 분석적으로 유효/무효가 정해진 선분·반례; 고의로 손상한 경로 | 유형별 오탐/누락, 공선점 분할 불변성, 경계 수치 민감도 |
| E3 해상도/보수성 | 동일 연속 장면에 1.0/0.5/0.25 m 격자, 알려진 유효 witness 경로 | 격자 미발견율, 길이·비용 변화, 시간·메모리; 미세 격자도 연속 최적해로 간주하지 않음 |
| E4 변경 추적 | 규칙 추가/거리 수정/하나씩 제거; 변경 전후 snapshot 보존 | 길이·굽힘 변화, 겹침/형상 차이, rule/source/object/segment 연결률 |
| E5 경유점/재탐색 | 순서·축·중심 이탈·자기 간섭 조건; exact와 heuristic 분리 | 유효 성공률, fallback율, gap(동일 문제의 정답이 있을 때만), 실패 원인 |

처음 10개 정도의 분석 가능한 예비 장면에서 기록/분모/정답 기준을 확인한 뒤,
30–50개의 기본 장면에 사전 고정한 시드·해상도·규칙 조건을 교차 적용한다.
이는 실험계획의 예시 개수이며 학위 통과 기준이나 통계적 검정력 보장은 아니다.
튜닝용 장면과 최종 평가 장면을 분리하고 실패/예산초과도 전부 기록한다.
결정론적 경로의 반복 실행은 시간 변동을 측정할 뿐 독립 장면 표본을 늘리지 않는다.
paired 장면 차이와 장면 단위 신뢰구간을 보고하고, 시간 반복을 독립 표본처럼 취급하지 않는다.

규칙 제거 실험은 feasible set이 달라지므로 알고리즘 우열 비교와 분리한다.
제약을 제거한 경로를 원래 규칙으로 검사한 결과도 보관한다.
`feasible_success_rate`는 독립적으로 feasible이 확인된 장면을 분모로 삼고,
unknown/continuous-feasible-but-grid-blocked/search-budget-exceeded를 각각 기록한다.
검증기의 신뢰도를 측정할 때 검증기 자신의 결과를 정답 라벨로 삼지 않는다.

논문 작성에서는 사용한 알고리즘·거리 판정의 출처를 인용하고, AI 도구의 코드 작성 보조 범위와
본인이 수행한 수정·검증을 기록한다. 제출 시 소속기관의 AI 활용 표기 지침을 확인한다.
현재 검토는 코드의 저작권 출처 전체나 학위 제출 규정까지 감사한 것은 아니다.

## 2026-10-12 P10C 후속 구현

위 표와 반례는 최초 검토 시점의 기록이다. 후속 P08c·P10A·P10B·P10C를 반영한 현재 상태는
ROADMAP과 ADR 0013~0016을 따른다. P10C는 동일한 물리 입력에 대해 규칙 추가·이격 수정·개별 제거를
대조하고, 출처 수정·중복 규칙의 중립 대조와 초안/변조 승인 차단도 확인한다.
전후 경로를 서로의 규칙으로 다시 검증하고 위반의 규칙·출처·객체·원본 구간 및 거리 연결을 검사한다.
실행 로그/CSV/기술 통계/PNG/PDF를 보존하며 알고리즘 비교(P10B)와 규칙 영향(P10C)을 구분한다.

이 합성 대조는 연구 흐름의 구현 근거를 보완했다. 단일 Zone family·평가 seed 2개에서의 연결 완전성이나
중립 대조 통과를 실제 법규의 완전성·실무 적합성·선행연구 대비 우월성으로 해석하지 않는다.
다음 연구 작업은 선행연구 원문 절/쪽과 같은 범위로 비교표·연구질문·주장 범위를 확정하고
브라우저 조작·WebGL 시연 기록을 추가하는 것이다. 정량 결과와 재현 명령은 ADR 0016에 기록한다.
